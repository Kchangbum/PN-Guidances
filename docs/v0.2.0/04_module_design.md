# v0.2.0 — Step 4. 모듈 설계: 결과 데이터 표시 범위

작성일: 2026-10-02 (Asia/Seoul)

상태: **결과 표시 부분의 상세 설계 초안, 구현·시험 전**.

기준: [아키텍처 설계](03_architecture_design.md), [기존 명명 규칙과 변수 정의](../Software_Lifecycle.md), [현재 시각화 파일](../../visualizeSimulation.m).

## 1. 범위와 원칙

이미 제공된 결과 데이터의 표시와 입력 확인만 다룬다. 가이던스 실행·계산·운동 모델·종료 판단·성능 평가를 설계하지 않는다. 전체 실행 환경의 상세 설계 완료를 의미하지 않는다.

사용자 요청에 따라 역할이 같은 변수와 함수는 기존 이름을 유지한다. 새로운 컨테이너와 표시 관리 정보에만 새 이름을 제안한다. 구조체 배열과 공통 표시 기능을 사용하고 클래스는 도입하지 않는다. 원본 코드 내용과 호출부는 변경하지 않는다.

## 2. 명명 규칙

원본 PPT 8~11장에 정한 규칙을 적용한다.

| 대상 | 규칙 | 이 설계에서의 적용 |
|---|---|---|
| 일반 변수 | camelCase | 기존 time 등 유지 |
| 개수 | n + 대상 | 신규 표시 관리 변수 nResults |
| 반복 인덱스 | i + 대상 | 신규 표시 관리 변수 iResult |
| Boolean | is / has / can + 의미 | 신규 입력 상태 isValid |
| 구조체 변수 이름 | PascalCase | 신규 결과 컨테이너 SimulationResults |
| 구조체 필드 | camelCase | name, time, data, source |
| 함수 | camelCase, 동작을 나타내는 이름 | 기존 visualizeSimulation 이름 유지 |
| 상수 | UPPER_CASE | 이번 설계에 새 상수를 추가하지 않음 |

일반 변수·함수의 언더바와 의미 불명확한 축약어를 지양한다. 설정 가능한 값을 상수로 분류하지 않는다. 이름 규칙 때문에 원본 파일을 자동으로 바꾸지 않는다.

## 3. 결과 컨테이너 정의

SimulationResults는 표시할 결과를 담는 구조체 배열의 제안 이름이다. 가이던스 실행 객체나 현재 상태 객체가 아니다. 아래 내용은 설계 제안이며 현재 MATLAB 파일에 이 구조체가 구현되어 있다는 뜻은 아니다.

| 이름 | 자료형·형상 | 역할 | 단위 |
|---|---|---|---|
| SimulationResults | 1×K 구조체 배열 | 제공된 결과 묶음 | 없음 |
| name | 스칼라 string | 결과 식별 및 범례 이름 | 없음 |
| time | double 벡터 | 해당 결과의 기존 시간 벡터 | s |
| data | 구조체 | 기존 표시 데이터의 보관 | 항목별 기존 단위 |
| source | 스칼라 string | 출처·적용 버전 설명 | 없음 |
| nResults | 정수값을 갖는 스칼라 | 표시 대상 결과의 개수 | 개 |
| iResult | 정수값을 갖는 스칼라 | 표시 대상 결과 인덱스 | 없음 |
| isValid | 스칼라 logical | 해당 입력이 표시 가능한 형식인지 여부 | 없음 |

K는 결과 묶음 수이며 각 결과의 시간 표본 수와 구분한다. time은 각 결과의 것을 유지하고 다른 결과와 길이가 같다고 가정하지 않는다. source를 확인할 수 없으면 미확인이라고 기록한다.

## 4. 기존 이름 보존

data 안의 기존 이력 변수는 이름과 의미를 유지한다. 이 문서에서 새 계산이나 변환 규칙을 추가하지 않는다. 실제 기존 이력과 표시 데이터의 이름 대응은 현재 파일을 기준으로 관리하며, 역할이 다른 변수를 같은 이름으로 합치지 않는다.

| 기존 이름 | 보존할 역할 |
|---|---|
| time | 표시 데이터의 시간 |
| targetStateHistory, missileStateHistory | 기존 상태 이력의 식별 이름 |
| geometryHistory | 기존 기하 이력의 식별 이름 |
| bankAngleHistory | 현재 시각화 함수에서 사용하는 뱅크각 이력 인수 이름 |
| lateralAccelCmdHistory | 기존 가속도 명령 이력의 식별 이름 |
| trajectoryAxes, headingAxes | 기존 궤적·기수각 화면의 축 이름 |
| rangeAxes, rangeRateAxes | 기존 거리·거리 변화율 화면의 축 이름 |
| losAngleAxes, losRateAxes | 기존 LOS 화면의 축 이름 |

위 표는 현재 소스의 이름 목록이며 유도 계산 또는 명령 생성의 설계가 아니다. 호출 측의 이름과 시각화 인수 이름이 다른 경우 각각의 범위를 기록하고 임의로 바꾸지 않는다. 사용자 발언의 visualizationSimulation.m에 대응하는 실제 함수·파일 이름은 visualizeSimulation이다.

값·표시 이름·단위는 각 표시 항목의 정의로 함께 관리하되, 이를 위해 모든 수치 배열을 새로운 중첩 객체로 감싸지는 않는다. 기존 단위는 원본 데이터에 유지하며 표시 변환이 원본 값을 덮어쓰지 않도록 한다.

## 5. 공통 표시 기능의 입출력 책임

| 구분 | 정의 |
|---|---|
| 이름 | visualizeSimulation의 표시 책임과 이름 유지 |
| 설계상 입력 | 결과 식별 정보와 기존 시간·표시 이력을 담은 결과 묶음 |
| 화면 출력 | 기존 Figure에서 같은 종류의 데이터를 구분해 표시 |
| 상태 안내 | 누락·형상 불일치·표시 실패의 대상과 이유 |
| 부작용 제약 | 원본 데이터와 계산 결과를 수정하지 않음 |

현재 함수는 기존 개별 인수를 받는다. 본 문서의 결과 컨테이너 제안이 현재 호출과 호환된다고 주장하지 않는다. 실제 함수 시그니처와 호출부 변경은 구현하지 않았다.

## 6. 입력 확인과 예외 처리

| 확인 항목 | 표시 규약 | 문제 발생 시 |
|---|---|---|
| 필수 정보 | 이름·시간·표시 데이터의 존재 확인 | 해당 항목과 부재 이유 안내 |
| 시간 이력 | 시간과 대응 값의 표본 수 일치 | 해당 표시를 생략하고 불일치 안내 |
| XY 데이터 | X와 Y의 표본 수 일치 | 해당 표시를 생략하고 불일치 안내 |
| 결과 간 길이 | 서로 달라도 각 결과의 것을 유지 | 임의 보간·절단·채우기로 맞추지 않음 |
| 출처 | 확인 가능 여부를 기록 | 미확인으로 명시 |
| 표시 실패 | 실패 항목을 구분 | 정상 표시로 위장하지 않고 안내 |

다른 결과를 복제해 없는 데이터를 대신 만들지 않는다. 입력 형식 확인과 알고리즘 시험의 합격은 서로 다르다.

## 7. 처리 순서와 표시 규약

1. 필수 정보와 표시 데이터 형상을 확인한다.
2. 표시 가능한 데이터를 구분하고 문제 항목을 기록한다.
3. 기존 Figure 구성을 유지한다.
4. 같은 종류의 제공된 데이터를 해당 Figure에 표시한다.
5. name을 사용해 범례를 표시하고 결과별 색·선 스타일을 일관되게 유지한다.
6. 누락·표시 실패 상태를 사용자에게 알린다.

색과 선 스타일은 다음과 같이 정한다. 결과 이름과 표시 순서를 연결해 모든 Figure에서 같은 규칙을 사용한다.

| 표시 순서 | 색 | MATLAB RGB | 선 스타일 | 선 두께 |
|---|---|---|---|---|
| 첫 번째 결과 | 파랑 | [0.0000, 0.4470, 0.7410] | 실선 (-) | 1.5 |
| 두 번째 결과 | 주황 | [0.8500, 0.3250, 0.0980] | 파선 (--) | 1.5 |
| 세 번째 결과 | 초록 | [0.4660, 0.6740, 0.1880] | 일점쇄선 (-.) | 1.5 |

기존 출력 항목·축 의미·단위를 유지하며 자동 저장 기능과 새로운 분석 항목은 추가하지 않는다. 이 표는 표시 규약이며 MATLAB 코드에 적용한 것이 아니다.

## 8. 함수 분리 기준과 단계 결과

공통 표시 진입점 하나를 중심으로 설계한다. 반복되는 표시 처리가 실제로 확인될 때만 보조 함수로 분리한다. Figure별 전용 파일과 별도 클래스는 만들지 않는다. 구체적인 보조 함수 목록은 구현하지 않았다.

명명 규칙, 결과 컨테이너, 기존 이름 보존, 입출력 책임, 입력·예외 처리, 표시 순서를 정리했다. 이는 결과 표시 부분의 설계 초안이다. MATLAB 원본·PPT 수정, 신규 실행·시험, GitHub 업로드는 수행하지 않았다.
