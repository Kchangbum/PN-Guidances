# v0.2.0 — Step 1. 변경 요구사항 분석

작성일: 2026-10-02 (Asia/Seoul)

상태: **사용자 요청 기록 및 요구사항 초안 작성, 최종 검토 전**.

이 문서는 대화에서 사용자가 정한 변경 목적과 범위를 정리한 산출물이다. 기존 [소프트웨어 생명주기 문서](../Software_Lifecycle.md)의 요구사항을 대체하지 않는다. 구체적인 유도 알고리즘 설계·구현·성능 비교 시험 계획은 포함하지 않는다.

## 1. 변경 목적

사용자는 기존 단일 가이던스 실행 프로그램을 세 가이던스의 결과를 구분해 함께 볼 수 있는 환경으로 확장하기를 원한다. 동시에 중복·불필요한 부분을 정리하고, 필요한 책임 분리와 재사용을 적용하되 불필요한 모듈화는 하지 않기를 원한다.

v0.2.0은 목표 버전 이름이며 구현 완료·검증 완료·배포 태그 생성을 의미하지 않는다.

## 2. 사용자가 확정한 범위

| 구분 | 사용자 요청 |
|---|---|
| 대상 | TPN, PPN, APN |
| 실행 목표 | 세 가이던스를 실행할 수 있는 환경 |
| 출력 범위 | 기존 시각화 파일의 각각의 Figure에서 세 가이던스의 결과를 비교할 수 있도록 표시 |
| 출력 예시 | 궤적 Figure 하나에 각 가이던스의 궤적을 구분되는 선으로 표시 |
| 코드 정리 | 가이던스마다 전체 코드를 반복 작성하는 방식의 중복을 줄임 |
| 구조 원칙 | 공통 처리의 재사용과 책임 분리·캡슐화를 지향 |
| 모듈화 제약 | 불필요한 함수·클래스·계층을 추가하지 않음 |

사용자가 언급한 visualizationSimulation.m에 대응하는 현재 실제 파일명은 `visualizeSimulation.m`이다. 이 문서는 현재 파일명으로 참조하며 파일을 변경하거나 이름을 바꾸지 않았다.

## 3. 변경 요구사항 목록

아래 CHG ID는 이번 변경 요청의 관리용 식별자다. 기존 REQ-001~005와 구분하며 새로운 계산식·기동 조건·성능 기준을 추가하지 않는다.

| ID | 변경 요구사항 | 출처 |
|---|---|---|
| CHG-01 | 대상 가이던스는 TPN, PPN, APN으로 한다. | 사용자 대상 지정 |
| CHG-02 | 세 가이던스의 실행 결과를 서로 구분할 수 있도록 관리한다. | 사용자 실행 환경 요청 |
| CHG-03 | 기존 시각화의 각 Figure에서 세 가이던스의 해당 결과를 함께 구분해서 표시한다. | 사용자 출력 범위 지정 |
| CHG-04 | 가이던스마다 전체 실행 코드를 복제하는 중복을 줄이고 공통 처리를 재사용한다. | 사용자 정리 기준 |
| CHG-05 | 책임 분리·캡슐화를 적용하되 목적이 명확하지 않은 모듈과 계층은 추가하지 않는다. | 사용자 모듈화 제약 |

## 4. 아직 결정하지 않은 사항

- 함수, 구조체, 클래스 등 구체적인 구현 수단.
- 모듈의 구체적인 구성과 인터페이스.
- 알고리즘 구현 방식, 실행 조건, 성능 평가와 수치 합격 기준.

사용자는 객체지향적인 구조를 지향한다고 설명했지만 클래스 도입 자체를 필수 요구로 확정하지 않았다. 구조 선택을 요구사항 단계에서 임의로 확정하지 않는다.

## 5. 원본 및 산출물 관리 제약

- 기존 원본 코드 수정 금지 조건은 유지한다. 이번 문서 생성은 코드 변경 승인으로 해석하지 않는다.
- 삭제·정리 후보는 이유와 영향부터 기록하고 자동 삭제하지 않는다.
- 기존 PPT의 단계 구성과 기존 요구사항을 임의로 변경하지 않는다.
- 문서 작성과 구현·시험·검증·배포 완료를 구분한다.
- 과거 시험 결과를 새 버전의 검증 결과로 표시하지 않는다.

## 6. 이번 단계의 결과

대상, 출력 범위, 중복 최소화와 모듈화 제약을 사용자 발언에 근거해 기록했다. 요구사항 초안은 작성되었으며 사용자 최종 검토 전이다. 코드·PPT 수정, 신규 알고리즘 시험, GitHub 업로드는 수행하지 않았다.

이 문서는 변경 범위 기록용이다. 다음 단계의 구체적인 미사일 유도 비교 환경 설계·구현·성능 시험을 제공한 것으로 해석하지 않는다.
