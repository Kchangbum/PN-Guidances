# v0.2.0 — Step 3. 소프트웨어 아키텍처 설계：결과 데이터 표시 범위

작성일: 2026-10-02 (Asia/Seoul)

상태: **아키텍처 초안 작성, 구현·검증 전**.

기준: [변경 요구사항](01_requirements.md), [시스템 설계](02_system_design.md), 사용자 원본 PPT의 Step 3 아키텍처 설계 분류.

## 1. 범위와 결정

제공된 결과 데이터를 구분해 표시하는 부분을 설계한다. 가이던스 계산·실행·운동 계산·종료 판단·성능 평가 구조는 포함하지 않는다. 이 문서를 전체 실행 환경의 아키텍처 설계 완료로 표시하지 않는다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 결과 보관 | 동일한 필드를 갖는 구조체 배열 | 결과별 정보를 묶고 동일한 방식으로 읽기 위함 |
| 표시 처리 | 공통 시각화 함수 | 결과마다 전체 표시 코드를 복제하지 않기 위함 |
| 클래스 | 현재 도입하지 않음 | 데이터와 표시 규칙 관리에 필요한 구조로 한정 |
| 파일 분리 | 기능 항목마다 새 파일을 만들지 않음 | 불필요한 모듈과 계층 증가 방지 |
| 보조 함수 | 반복되는 표시 처리가 확인될 때만 분리 | 분리 목적이 명확한 처리만 재사용 |

구조체 배열은 결과 데이터의 컨테이너이며 가이던스 실행 객체가 아니다. 이 문서에서는 함수의 실제 호출 형식과 MATLAB 코드 변경을 확정하지 않는다.

## 2. 책임과 경계

| 책임 | 담당 경계 | 수행 내용 | 범위 밖 |
|---|---|---|---|
| 데이터 제공 | 기존 시스템 | 표시 대상 데이터와 식별 정보를 제공 | 이 문서에서 제공 방식이나 계산 과정을 변경하지 않음 |
| 입력 확인 | 시각화 진입점 | 필수 정보, 표시 데이터와 시간의 길이 확인 | 누락값 생성, 수치 보정, 알고리즘 판정 |
| 그래프 표시 | 공통 시각화 처리 | 기존 Figure 구성에 제공된 데이터를 구분해 표시 | 새로운 성능 평가와 비교 지표 계산 |

각 행은 논리적 책임이다. 별도 클래스·파일을 반드시 생성해야 한다는 뜻은 아니다. 기존 visualizeSimulation.m의 역할을 기준으로 표시 책임을 유지한다.

## 3. 결과 데이터 구조

각 결과는 다음 필드를 가진다. 필드 이름은 이번 대화에서 정한 일반적인 결과 표시용 이름이며 가이던스별 내부 상태를 정의하지 않는다.

| 필드 | 내용 | 관리 원칙 |
|---|---|---|
| name | 결과 식별 이름 | 범례의 식별 이름으로 사용 |
| time | 해당 결과의 시간 벡터 | 다른 결과와 길이가 같다고 가정하지 않음 |
| data | 해당 결과의 표시 데이터 | 기존 데이터의 의미·단위를 유지. 세부 내부 구성은 미정 |
| source | 데이터 출처·적용 버전 정보 | 알 수 없는 출처는 미확인으로 명시 |

결과별 시간과 데이터를 독립적으로 보존한다. 같은 시간 벡터를 강제로 적용하거나 길이를 맞추기 위해 데이터를 임의로 채우지 않는다. 데이터가 없으면 다른 결과를 복제해 대신 사용하지 않는다.

## 4. 인터페이스 책임

| 경계 | 받는 정보 | 전달하거나 알리는 내용 |
|---|---|---|
| 기존 시스템 → 시각화 진입점 | 결과 이름·시간·표시 데이터·출처 | 표시 대상 결과 |
| 입력 확인 → 표시 처리 | 표시 가능한 결과와 확인 상태 | 표시 가능한 데이터 및 부재·불일치 안내 |
| 표시 처리 → 사용자 | 기존 Figure 구성과 식별 규칙 | 구분되는 선·범례, 표시 실패 안내 |

실제 함수 시그니처, data의 내부 필드와 기존 호출부 변경은 정의하지 않았다. 데이터 출처와 확인 상태는 표시 근거를 설명하며 시험 합격을 의미하지 않는다.

## 5. 데이터 흐름

```text
기존 시스템이 제공한 결과
  이름 / 각 결과의 시간 / 표시 데이터 / 출처
                    ↓
       시각화 진입점의 입력 확인
                    ↓
           공통 시각화 처리
                    ↓
    기존 Figure에서 같은 종류의 데이터 표시
      결과별 선과 범례로 구분 / 상태 안내
```

## 6. 표시 규약

- 같은 종류의 데이터는 같은 Figure에서 표시한다.
- 결과별 색과 선 스타일은 모든 Figure에서 일관되게 유지한다. 첫 번째 결과는 파랑 실선, 두 번째 결과는 주황 파선, 세 번째 결과는 초록 일점쇄선으로 표시한다. 이름과 표시 순서의 연결은 한 번 정한 뒤 Figure마다 바꾸지 않는다. 구체적인 값은 04_module_design.md의 표시 규약을 따른다.
- 범례는 name의 식별 이름을 사용한다.
- 기존 축의 의미와 단위를 유지한다.
- 데이터 부재·길이 불일치·표시 실패를 숨기지 않는다.
- 선의 모양만으로 정확성·성능·우열을 판정하지 않는다.
- 기존 시스템에 없는 자동 저장 기능이나 그래프 항목을 추가하지 않는다.

## 7. 모듈화·캡슐화 원칙

데이터 제공 부분은 공통 표시 기능에 필요한 정보만 전달하고, 표시 기능은 제공된 정보를 읽는 책임으로 한정한다. 원본 데이터를 변경하지 않는다.

반복되는 표시 처리가 확인된 경우에만 보조 함수 분리를 검토한다. 한 번만 사용하는 짧은 처리를 무조건 분리하지 않으며, 책임 표의 항목 수에 맞춰 파일·클래스를 늘리지 않는다. 클래스 도입은 현재 설계에 포함하지 않는다.

## 8. 요구사항 연결과 단계 결과

| 변경 요구사항 | 이번 문서의 대응 | 상태 |
|---|---|---|
| CHG-01 | 결과 이름으로 대상 식별 | 구현 여부나 알고리즘 실행을 보장하지 않음 |
| CHG-02 | 결과 데이터의 분리 보관 부분만 정리 | 가이던스 실행 환경은 범위 밖 |
| CHG-03 | 공통 Figure 표시와 식별 규약 | 표시 부분의 설계 초안 |
| CHG-04 | 공통 표시 처리 재사용 부분만 정리 | 전체 실행 코드 중복 정리는 범위 밖 |
| CHG-05 | 클래스 미도입·필요한 보조 함수만 분리 | 표시 부분의 구조 원칙 정리 |

책임 구성, 결과 구조체의 필드, 논리 인터페이스, 데이터 흐름과 표시 규약을 정리했다. 다음 상세 설계에서 사용할 실제 data 구성·함수 시그니처는 이 문서에서 확정하지 않는다. 원본 MATLAB 코드·PPT 수정, 파일 삭제, 실행·시험·GitHub 업로드는 수행하지 않았다.
