# 요구사항·산출물·검증 추적표

요구사항은 원본 PPT 2장, 단계는 원본 PPT 3~18장을 기준으로 한다. 시험 ID와 그림 ID는 기존 MD 및 대화에서 정리한 것이며 PPT에 모두 실려 있는 것으로 해석하지 않는다.

| 요구사항 | 설계 연결 | 현재 구현 파일 | 기존 시험 연결 | 현재 확보된 증거·상태 |
|---|---|---|---|---|
| REQ-001 | 시스템·아키텍처·모듈 설계 | computeKinematics.m | UT-07~12, EX-01~02 | 기존 궤적·기수각·예제 PNG. 수치 원본 부재, 현재 합격 미확정 |
| REQ-002 | 조건 설정·Config 정의 | configuration.m, main.m | 기존 초기 상태 확인 기록 | 현재 설정 파일은 존재. 시험 데이터 부재, 미재검증 |
| REQ-003 | 모듈·명령 관련 설계 | computePNGuidance.m, computeBankCommand.m | UT-04~06, IT-01~02 | 명령 PNG는 존재. 수치 원본 부재, 미재검증 |
| REQ-004 | 매니저 흐름·이력 설계 | main.m | IT-02~04, ST-01~03, EDGE-01~03 | 과거 판정은 MD에 기록. 현재 시험 코드·데이터 부재 |
| REQ-005 | Visualization 설계 | visualizeSimulation.m | ST-02, FIG-01~05 계획 | 기본 PNG 6개 존재. 추천 그림 전체가 제작된 것은 아니며 인수 판정보류 |

## 원본과 현재 파일의 차이

- PPT 17장은 initializeConfiguration.m을 제시하지만 현재 설정 파일은 configuration.m이다. 기존 파일을 그대로 연결한다.
- PPT 4·14장의 PN 표기와 현재 활성 PPN 구현의 표현은 일치하지 않는 부분이 있다. 원본 또는 코드를 자동 수정하거나 일치 판정하지 않는다.
- PPT 18장은 phi_cmd = 0 단위 시험만 명시한다. 다른 시험 분류와 합격표는 기존 대화·MD의 보완 관리 항목이다.
- 단계 결과는 문서 존재, 파일 보존 확인, 시험 합격을 구분한다. 현재 원본 데이터 부재로 과거 시험 판정을 재현 확인하지 못했다.

## 변경 기록 규칙

변경 이유 → 요구사항 ID → 영향받는 설계 절·파일 → 시험 ID → 실행 결과·버전 순서로 기록한다. 관련 항목만 갱신하며 영향 없는 단계는 검토 결과를 명시한다. 과거 결과는 유지하고 새 결과를 연결한다.
